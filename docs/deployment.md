# Deployment

Lemniro is exported as static files and published to [GitHub Pages](https://ddomology.github.io/Lemniro/). There is no application server to run after deployment.

## Automatic pipeline

The workflow in `.github/workflows/pages.yml` runs on:

- A push to `main`: build, check, and deploy.
- A pull request: build and check, without publishing.
- Manual dispatch: build and check; publish only when the selected branch is `main`.

The build job installs the TeX toolchain on Ubuntu 24.04, runs `npm ci`, compiles the source documents, and exports Next.js to `out/`. It then tests source validation and the generated HTML/PDF before checking TypeScript. Export verification checks article content, SVG visuals and their compiled assets, internal links and assets under the production base path, the sitemap, and RSS. The workflow also checks that the export contains `index.html`, `sitemap.xml`, and the actual `.nojekyll` file. The deploy job receives only an artifact that passed all these checks.

The build token has `contents: read`. Only the deployment job receives `pages: write` and `id-token: write`. Dependencies are installed from the lockfile, and the official GitHub actions are pinned to release commit hashes. Deployment uses the `github-pages` environment.

## Repository setup

In **Settings → Pages → Build and deployment**, select **GitHub Actions** as the source. The repository must allow Actions and GitHub Pages. The deployment environment should allow the `main` branch.

No deployment secret or personal access token is required by this workflow. GitHub supplies a token and the deployment identity for each run.

To inspect a run, use the repository's **Actions** tab. A failed build leaves the previous Pages deployment in place. Fix the source and push again; the next successful run publishes the updated export.

## URL configuration

The production workflow sets:

```text
NEXT_PUBLIC_BASE_PATH=/Lemniro
NEXT_PUBLIC_SITE_URL=https://ddomology.github.io/Lemniro
```

The repository name is case-sensitive in the path: this project uses **Lemniro**, with a capital `L`. The base path is used for navigation and static assets. The absolute site URL is used for discovery metadata.

For a custom domain served at the domain root, update those values to an empty base path and the HTTPS origin respectively, then configure the domain in GitHub Pages and add the required `CNAME` file. Verify the exported links, canonical URLs, and sitemap after any URL change.

Local development uses the site root by default. When previewing an export built with `/Lemniro` as its base path, serve it under that same prefix; otherwise its assets will be requested from a directory your local server does not provide.

## Build products

- `.build/` holds intermediate TeX compilation files and logs.
- `generated/content.json` contains the compiled article data consumed by React.
- `public/tex/` contains generated article assets, including PDFs and downloadable sources.
- `out/` is the deployable static website.

These outputs are regenerated by the build. Commit original TeX, site code, configuration, and the npm lockfile instead.
